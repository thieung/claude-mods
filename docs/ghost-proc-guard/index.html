ghost-proc-guard
All mods /procs Install Source

One dev server per checkout.

Claude forgets a server is running, starts another, and the tool quietly moves to the next free port. ghost-proc-guard stops that launch and tells Claude which server already holds the port.

Install the mod Read the source

A Claude Code mod. Needs Claude Code 2.1.287 or later. Tested on macOS.

    What the guard checks
    
          
    Every dev command Claude runs through its Bash tool is read before it starts.
    
        
    
        
    
          
    
            
    Duplicate launches
    
            
    
              
    The guard works out which ports the launch will bind and refuses it if one is taken, or if a server already runs from the same folder. Claude gets the owner: command, folder, launching session and process ids, plus what to do next.
    
              
    npm run dev, pnpm dev, vite, next dev, astro dev, wrangler dev, uvicorn, python -m http.server and more.
    
            
    
          
    
          
    
            
    Monorepos
    
            
    
              
    For turbo, pnpm -r / --filter, nx, lerna and npm workspaces, it reads every package that runs the task. Each port comes from the script flag, then the tool's config (vite.config, astro.config, wrangler.toml), then the tool's default.
    
            
    
          
    
          
    
            
    Worktrees
    
            
    
              
    Each server is placed in its git worktree, including ones nested under .claude/worktrees/. A worktree launch that needs a port another checkout holds is refused, with a warning not to reuse a server running other code.
    
            
    
          
    
          
    
            
    Who started what
    
            
    
              
    Launches carry GHOST_PROC_GUARD_SESSION=<session id> in their environment, so each server stays attributed to the session that started it, even after that session is gone.
    
            
    
          
    
        
    
      
    
    
    

    
    
      
    
        
    
          
    Clean up with /procs
    
          
    Type /procs to open a pane with the servers Claude started, in this session and earlier ones, and the other servers in the project. One row per app.
    
          
      
            
    • Stop sends TERM to the whole app process tree. Press again to send KILL.
      • 
            
    • Claude's own processes and your interactive shells are never touched.
      • 
            
    • A new session warns about servers left running by earlier ones, and the status line shows how many are running.
      •

    Install
    
          
    Run these inside Claude Code. The mod lives in the thieung-mods marketplace, next to worktree-guard and ak-cockpit.
    
          
    A mod runs with the same access as Claude Code itself: files, processes, network. Read the source before installing.
    
        
    
        
    
          

    /plugin marketplace add thieung/claude-mods
/plugin install ghost-proc-guard@thieung-mods
/reload-plugins
    
        
    
      
    
    
    

    
    
      
    
        
    
          
    When you want two
    
          
    Tell Claude to prefix the command with GHOST_PROC_GUARD=allow. The guard asks Claude to do this only after you confirm, so a second server is always your call.
    
          
    If a hook fails, the command runs as if the guard were absent.
    
        
    
        
    
          
    Limits
    
          
      
            
    • Only commands Claude runs through its Bash tool are checked. What you type in your own terminal is not.
      • 
            
    • Ports computed in code, such as Number(process.env.PORT), are not read; the tool default is assumed.
      • 
            
    • Workspace globs are expanded one level (packages/*); ** globs are skipped.
      • 
            
    • macOS only for now. It relies on lsof and BSD ps -E for session attribution.
