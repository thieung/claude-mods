ghost-proc-guard · port busy

One dev server per checkout.

A Claude Code mod that stops Claude from starting a second copy of your app on the next free port, and cleans up the servers earlier sessions left running.

Install in Claude Code 2.1.287 or later 
/plugin marketplace add thieung/claude-mods
/plugin install ghost-proc-guard@thieung-mods
/reload-plugins

What it catches

Every case below was reproduced with real headless Claude sessions before release. The guard only steps in when Claude actually tries to launch; when Claude checks first and reuses the running server, nothing is blocked.

Claude forgets the server is up

After a compaction or a long thread, Claude runs pnpm dev again. Vite would quietly move to 5174 and you would have two copies of every app.

refused · A server is already listening from …/app (started by this session); processes: 46215

Two sessions, one project

A second Claude session tries to start the app while the first one's servers are still up. It learns who owns them and asks you before stopping anything.

refused · (started by Claude session 62c1b24c); the owner is another session, so Claude asks first

A worktree reaches for taken ports

In a turbo monorepo the guard reads every package's script and config to know the ports a launch needs, then places each running server in its git worktree.

refused · Ports 5321, 5322 are already in use [another worktree: …/mono]

See and stop what Claude started

Type /procs to open a pane beside the transcript. Each app is one row, however many processes it runs: wrangler's runtime helpers and internal sockets are folded in and hidden.

  • Stop sends TERM to the whole app tree; a second press sends KILL.
  • Claude's own processes and your interactive shells are never touched.
  • Every launch carries GHOST_PROC_GUARD_SESSION in its environment, so servers keep their owner even after they are orphaned.
  • A new session warns you about servers earlier sessions left running.

How it knows which ports a launch needs

For a workspace runner (turbo, pnpm -r or --filter, nx, lerna, npm workspaces) it walks every package that runs the task, honours turbo's --filter, and takes the first answer from this order.

Script flag

wrangler dev --port 8788, PORT=4000, vite --port 5175

→ Tool config

server.port in vite or astro config, [dev] port in wrangler.toml or .jsonc

→ Tool default

The port the tool binds when nothing else says otherwise

Vite5173vite, vite dev (vite preview uses 4173)

Limits

  • Only commands Claude runs through its Bash tool are checked. What you type in your own terminal is not.
  • Ports computed in code, such as Number(process.env.PORT), are not read; the tool default is assumed.
  • Workspace globs are expanded one level (packages/*).
  • Tested on macOS. It relies on lsof and BSD ps -E.
  • If you really want a second server, confirm it and Claude prefixes the command with GHOST_PROC_GUARD=allow.
  • If the guard itself fails, the command runs as if it were not installed.
